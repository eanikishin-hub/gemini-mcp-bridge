# Инструкция для Claude: подключить владельца к Gemini и NotebookLM

Этот файл тебе дал владелец. Его цель — чтобы ты (Claude) мог сам работать с его Gemini и NotebookLM:
рисовать картинки, читать и продолжать его чаты в Gemini, работать с блокнотами NotebookLM.

**Как работать с владельцем:** он не программист. Пиши простым русским языком, без жаргона. Всё, что можешь,
делай сам. От владельца нужно только: войти в Google в своём браузере и выгрузить куки, добавить коннектор
в claude.ai, ввести пароль на странице подключения. Каждый такой шаг объясняй по пунктам: куда нажать,
что вставить.

**Чего не делать:** не обещай, что всё безопасно, — честно расскажи про риски (раздел 4). Не проси пароль
от Google: он не нужен. Куки и пароли не пиши в чат и не клади в git.

---

## 0. Сначала проверь условия

1. **Сервер не в России.** Проверь: `curl -s https://ipinfo.io/country`. Если ответ `RU`, остановись
   и скажи владельцу, что Gemini и NotebookLM с российского адреса не работают. Нужен сервер за рубежом.
2. **Ты root на Ubuntu или Debian** (`id -u` → 0, `cat /etc/os-release`). Если нет, скажи, чего не хватает.
3. **Есть ли свой адрес (домен).** Он нужен, чтобы коннектор работал в claude.ai и на телефоне.
   Посмотри, как устроен адрес мастерской: `ls /etc/nginx/sites-enabled/`, `cat` нужного файла.
   - Нужны два поддомена: `gemini.<домен>` и `notebooklm.<домен>`, A-запись на IP этого сервера
     (`curl -s https://ipinfo.io/ip`).
   - Если у тебя есть доступ к DNS (например, ключ Cloudflare на сервере), заведи записи сам.
   - Если доступа нет, дай владельцу точный текст: «в панели DNS добавить запись A, имя `gemini`,
     значение `<IP>`; так же для `notebooklm`». Жди, пока `dig +short gemini.<домен>` не покажет IP.
   - Если адреса нет и не будет: Gemini можно поставить в режиме «только в мастерской» (раздел 1, вариант Б).
4. **Подписка Claude.** Свои коннекторы в claude.ai есть на платных планах. Добавлять их можно в браузерной
   версии: приложение на компьютере не нужно.

## 1. Мост Gemini

1. Скачай и **прочитай код**, прежде чем ставить. Проверь сам, что куки уходят только на адреса Google:
   ```bash
   git clone https://github.com/eanikishin-hub/gemini-mcp-bridge /root/gemini-mcp-bridge
   cd /root/gemini-mcp-bridge && grep -rn "https://" src | grep -v google
   ```
   Должны найтись только две строки: `https://claude.ai` (откуда разрешено подключаться к мосту) и проверка
   `startswith("https://")` (мост скачивает картинку по ссылке, только если её дали явно). Больше никуда
   программа не ходит. Куки читаются только в `login.py` и `server.py`: проверь, что дальше Google они не уходят.
2. Установи:
   - **А (с адресом, рекомендуется):** `bash install/install.sh gemini.<домен>`
   - **Б (без адреса, только в мастерской):** `bash install/install.sh`, затем выполни команду
     `claude mcp add …` из файла `/root/most-gemini-dostup.txt`.
3. **Вход в Google.** Попроси владельца (объясни по шагам):
   1. В Chrome на своём компьютере создать **отдельный профиль** только для моста (значок профиля справа
      вверху → «Добавить»). Это важно: если взять куки из обычного браузера, браузер и мост будут перебивать
      друг другу вход.
   2. В этом профиле войти в Google (аккаунт с подпиской Gemini) и открыть https://gemini.google.com.
   3. Поставить расширение **Cookie-Editor**, на странице Gemini нажать его значок → **Export** → **JSON**.
      Текст скопируется. Вставить его в пустой файл `cookies.json`.
   4. Передать файл тебе (загрузить в мастерскую). Больше этот профиль Chrome не открывать
      и из Google в нём **не выходить**: выход отключит и мост.
   Затем выполни `gemini-vhod --json /путь/к/cookies.json` и **сразу удали файл**.
   Предупреди владельца: эти куки — ключ ко всему Google-аккаунту, их можно давать только своему Claude
   на своём сервере.
   Если на сервере есть рабочий стол с Chrome, вместо этого можно запустить `gemini-vhod` без параметров:
   откроется окно, владелец войдёт в Google сам. Сначала поставь
   `/opt/most-gemini/venv/bin/pip install playwright`.
4. **Коннектор (вариант А).** Попроси владельца:
   claude.ai → Настройки → Коннекторы → «Добавить свой коннектор». Название `Gemini`, адрес
   `https://gemini.<домен>/mcp`. Откроется страница с паролем: пароль лежит в `/root/most-gemini-dostup.txt`,
   покажи его владельцу. Права: всё «Разрешать всегда», кроме `gemini_delete_chat` — ему «Спрашивать».
5. **Проверка.** Вызови `gemini_usage`: вход должен быть «есть». Сделай одну картинку, например
   «кружка на деревянном столе, 3:4». Покажи результат владельцу.

## 2. NotebookLM

Ставится открытая программа [notebooklm-py](https://github.com/teng-lin/notebooklm-py). У неё есть подробное
руководство, следуй ему: `docs/mcp-guide.md`, раздел «Remote deployment», и `docs/installation.md`.
Коротко, что получилось у автора этой инструкции:

1. Установка в отдельное окружение: `python3 -m venv /opt/notebooklm/venv && /opt/notebooklm/venv/bin/pip install "notebooklm-py[mcp,browser]"`.
2. Вход в Google:
   - без рабочего стола — куки из того же отдельного профиля Chrome (Cookie-Editor на
     https://notebooklm.google.com → Export → JSON), затем `notebooklm auth import-cookies файл.json`;
   - либо способ из руководства `login --master-token` (он сам переживает истечение входа).
   Проверка: `notebooklm auth check` и `notebooklm list`.
3. Служба systemd: `notebooklm-mcp --transport http --host 127.0.0.1 --port 9420` с настройками
   `NOTEBOOKLM_MCP_OAUTH_PASSWORD=<случайные 20+ символов>`,
   `NOTEBOOKLM_MCP_OAUTH_BASE_URL=https://notebooklm.<домен>` (без `/mcp`) и `NOTEBOOKLM_MCP_TRUST_PROXY=1`.
   Перед ней — nginx на `notebooklm.<домен>` с сертификатом (`certbot --nginx`), как в установщике Gemini.
4. Коннектор: название `NotebookLM`, адрес `https://notebooklm.<домен>/mcp`, пароль — тот, что в
   `NOTEBOOKLM_MCP_OAUTH_PASSWORD`. Права: всё разрешить, кроме удаления и открытия доступа другим людям:
   им «Спрашивать».

На что наступил автор:
- **Вход продлевает только одна программа.** Если запускаешь и `notebooklm-server`, и `notebooklm-mcp`,
  второму поставь `NOTEBOOKLM_DISABLE_KEEPALIVE_POKE=1`. Иначе они перебивают друг другу вход в Google.
- **Если коннектор то и дело просит войти заново** (claude.ai в браузере и приложение выбивают друг друга),
  значит, при каждом продлении отзывается старый пропуск. Посмотри, как в текущей версии устроен срок жизни
  пропусков коннектора, и сделай так, чтобы старый пропуск не отзывался.

## 3. Google Flow

У автора инструкции подключить Flow не получилось: Flow видит его аккаунт в российском регионе.
Не обещай владельцу Flow. Если он попросит, сначала проверь, открывается ли https://labs.google/fx/tools/flow
под его аккаунтом.

## 4. Риски — расскажи владельцу честно

- Путь неофициальный: правила Google запрещают заходить в сервисы программой. Чаще всего вход просто
  «протухает» и его надо обновить. Блокировок аккаунта за такие мосты автор в жалобах не нашёл, но гарантий нет.
- Куки — ключ ко всему Google-аккаунту. Храни их только на сервере, файлы с ними удаляй сразу после входа.
- Не долби Gemini: у моста есть предохранитель (паузы и 50 картинок в сутки), не обходи его.

## 5. В конце — итог владельцу

Коротко и простыми словами: какие коннекторы работают, их адреса, где лежат пароли (`/root/most-gemini-dostup.txt`
и твоя запись про NotebookLM), что делать, если вход протух («попроси Claude обновить вход в Google для
Gemini / NotebookLM»), и одна пробная картинка.
